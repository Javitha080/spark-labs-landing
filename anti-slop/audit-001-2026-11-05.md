# Anti-slop audit 001 — `/leadership` macOS desktop upgrade

**Date:** 2026-11-05
**Scope:** everything shipped in the `/leadership` upgrade (React Bits Dock, FeralUI Fur boot wordmark, feralui gradient wallpaper, GSAP window/popover motion, Finder Members sidebar, GlareHover preview) plus the existing page it landed on.
**Method:** audit run AFTER the work, per the antislop filter. Click-through was scripted with Python Playwright (headless msedge): 25 checks, 0 failures, 0 real console errors. Screenshots reviewed at desktop, mobile, boot, and menu states. Evidence lives in `D:\Pentesting\rea\tmp\opencode\` (scripts, `clickthrough-report.json`, `shots/`).

## Resolved during this pass (logged for the record, no approval needed)

**A. Route-killing Draggable crash (was functional, not stylistic).**
`MacOsFolder.tsx` and `MacOsWindow.tsx` passed `bounds: ".macos-desktop"` as a selector string. Inside an active `useGSAP` scope, GSAP resolves selector strings against the scope element itself, so the ancestor desktop can never match. `Draggable` then read `.nodeType` off `undefined` (verified in `node_modules/gsap/gsap-core.js` `toArray` and `Draggable.js` `_getBounds`) and the ErrorBoundary bounced the user home. Fixed by passing the element directly (`closest(".macos-desktop")`), verified by a scripted drag (folder transform moved `translate3d(1215px, 500px)` to `translate3d(1167px, 464px)`).

**B. Fur wordmark scrambled glyphs.**
The boot wordmark captured as overlapping glyphs ("YICDVwP"). Forensics: the canvas bitmap itself is clean (six well-separated glyphs, confirmed by dumping the live canvas via `toDataURL` and by an isolated rerun of the package's silhouette math at 240x60). The scramble came from the HTML placeholder span under the coat: it never unmounted after the lazy Fur mounted, its 38.4px glyphs sit at different metrics than the drawn 51.6px glyphs, and the white shapes peeked through the fur's transparent hair gaps. Fixed by making the span the `Suspense` fallback only (plus the reduced-motion stand-in). Verified: normal boot reads as clean furry letters with no white bleed; reduced motion shows the plain span with zero fur canvases. Two earlier suspicions were disproven along the way: the hover lean-in transform (`fur.css` scale 1.015 / rotate -0.4deg on hover) and a font-measurement race. A gray ring in some captures is the headless test browser's rendered pointer indicator, not page content.

## Open findings — fix only what you approve

**RESOLUTION (2026-11-05, same day):** you approved all three; each was shipped
and verified below.

**1. (HIGH) Silent empty desktop when the member fetch loses the race.**
`fetchTeamMembers` (`src/pages/LeadershipPage.tsx`) raced Supabase against a 4s timeout, fell back to a second query, and on total failure rendered an honest empty desktop: no member tiles, no folders, no error, no retry. In test runs this happened on roughly half of cache-cold loads. The macOS fiction made it read as "the computer booted fine but there is no one here."
**Shipped fix:** a Finder-style empty-state card (`EmptyDesktopHint`) with title/body that differ between "registry didn't respond" (fetch error/timeout) and "no members published" (ok + 0 rows), an aria-live region, and a Try again button that re-runs the fetch honestly. The dock keeps a "Loading members" tile while the fetch races, and the dock itself is now mounted outside the content branches so Home and Restart stay reachable in loading and empty states. Verified in a scripted run that blocks all Supabase requests: card appears, Retry while blocked re-shows the card, unblocking + Retry brings back all 13 folders and tiles.

**2. (LOW) The dusk wallpaper's role is undocumented.**
`public/assets/yic-dusk-wallpaper.webp` is the desktop wallpaper; its palette quietly carries the page's brand tie-in (echoes the dusk gradient used for accents). Nothing in the code explained the choice (R-31).
**Shipped fix:** an expanded comment beside the wallpaper usage naming the FeralUI Gradient Builder recipe (style flow, colours `#070B13 #232059 #7C3AED #D946EF`, soften 42, grain 7) and why it is a WebP export.

**3. (LOW) Stale animation doc entry.**
`docs/GSAP-WEBSITE-MAP.md` documented a `MacOsDock` component that was deleted; the dock is the vendored React Bits `Dock` (`src/components/reactbits/Dock.tsx`) wired in `LeadershipPage.tsx`.
**Shipped fix:** all five stale entries updated: the maintenance note, the per-route table, the component inventory table, the unused-code section, the `quickTo` row (now credited to the page's cursor follower, where quickTo actually lives), and the file map. Remaining `MacOsDock` mentions are deliberate deletion-history notes.

**4. (NEW, LOW, approved) Menu-bar popovers dismiss by mouse only.**
While hardening the click-through harness it surfaced that the menu bar's
popovers (Finder/File/... and Apple) close only via `mousedown` outside the
bar (`MacOsMenuBar.tsx` useEffect). There was no Escape keydown wiring, so a
keyboard user could open a popover with `Enter` but had no keyboard dismissal;
the earlier audit wording "Apple and system menus with Escape" was wrong (the
old check asserted a tautological locator and Escape was never tested
meaningfully).
**Shipped fix (2026-11-05):** a window `keydown` listener in `MacOsMenuBar`
sets `activeMenu(null)` on Escape, matching macOS. Verified by the harness's
two new steps: "system menu reopens" and "system menu closes on Escape"; the
full run reports 29/29 PASS, 0 real console errors. ESLint on the file: clean.
